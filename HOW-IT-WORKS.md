# Как устроен этот проект

Документ для тех, кто только начинает программировать. Здесь простыми
словами объясняется, из чего состоит игра и как она попадает в интернет.

## Часть 1. Из чего состоит игра

Всего два файла делают всю игру:

```text
index.html   — «каркас» страницы: тег <canvas> (холст 600x400)
               и немного CSS, чтобы холст был по центру экрана
game.js      — вся логика игры (~1000 строк JavaScript)
```

`index.html` в конце подключает `game.js` строкой
`<script src="game.js"></script>` — и браузер запускает игру.

## Часть 2. Как работает игра внутри

Как и почти любая игра, она крутится в **игровом цикле** — функции,
которая вызывает себя примерно 60 раз в секунду:

```text
┌─────────────────────────────────────────────┐
│  1. Прочитать нажатые клавиши (input)        │
│  2. Обновить состояние мира (update):        │
│     куда сдвинулся игрок, летят ли пули,     │
│     столкнулся ли враг с игроком и т.д.      │
│  3. Перерисовать кадр (draw):                │
│     стереть холст и нарисовать всё заново    │
└──────────────┬──────────────────────────────┘
               │ повторять 60 раз в секунду
               └──────────────────────────────►
```

Всё состояние игры — это обычные переменные в начале `game.js`:
позиция игрока, массив врагов, массив монет, счёт, жизни.
Уровни переключаются сменой набора препятствий и параметров врагов.

## Часть 3. Как код попадает на сайт

Игра уже опубликована: **https://canvas-game.apps.botops.ru**

Ничего загружать руками не нужно — работает автодеплой.
Схема:

```text
ты делаешь:  git push  (в ветку master)
                    │
                    ▼
        GitHub запускает GitHub Actions
        (файл .github/workflows/deploy.yml)
                    │
                    ▼
        робот на чистой машине ubuntu:
          1. скачивает код репозитория
          2. копирует index.html + game.js в папку dist/
          3. отправляет dist/ на сервер по SSH
                    │
                    ▼
        сервер распаковывает файлы и
        переключает сайт на новую версию
                    │
                    ▼
        https://canvas-game.apps.botops.ru обновлён
```

Обычно весь путь от пуша до обновления сайта занимает меньше минуты.

### Что делать после изменения кода

```bash
git add .
git commit -m "описание изменения"
git push
```

После пуша можно открыть вкладку **Actions** в репозитории на GitHub —
там видно, как идёт деплой. Зелёная галочка = сайт обновлён.
Красный крест = что-то пошло не так, внутри шага виден текст ошибки.

### Если новая версия сломана

На сервере хранятся последние 5 сборок. Откат одной командой:

```bash
botops-static rollback canvas-game
```

Либо отменить коммит (`git revert`) и запушить — это тоже деплой.

## Где что лежит

| Что | Где |
|---|---|
| Код игры | этот репозиторий: `index.html`, `game.js` |
| Workflow автодеплоя | `.github/workflows/deploy.yml` |
| Живой сайт | https://canvas-game.apps.botops.ru |
| Локальная копия репозитория | `/home/devuser/ai-projects/canvas-game` |

## Полезно знать

- Для локальной проверки достаточно открыть `index.html` в браузере —
  никакой сборки и установки зависимостей нет.
- Деплой срабатывает **только** на пуш в `master`. Коммиты в других
  ветках сайт не трогают.
- SSH-ключ в workflow умеет только деплоить этот сайт — даже если его
  украдут, с ним нельзя получить shell на сервере или тронуть чужие сайты.
